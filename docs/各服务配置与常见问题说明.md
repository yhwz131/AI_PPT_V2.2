# 各服务配置文件与常见问题说明

## 关于文件名前缀「jna」

本仓库中部分技术文档以 **`jna` 开头**（例如 `jnaaippt_architecture_v1.md`、`jnadigital_human_data_flow.md`）。**仓库内未对「jna」给出权威全称或英文展开**，可视为**项目组内部用于归档「架构 / 数据流 / 服务说明」等技术文档的文件名前缀**。与产品名 **AIPPT** 连写时常见形式为 **`jna` + `aippt`**，例如 `jnaaippt_architecture_v1.md` 表示与 AIPPT 相关的系统架构文档（v1）。若需对外统一说明，可在项目 README 或 `docs` 索引中自行定义缩写含义。

**说明：** 本文已采用**中文文件名**；其余 `jna*.md` 仍为历史沿用的英文文件名，交叉引用未改动的文档时仍使用原文件名。

---

本文汇总 PPTTalK 仓库内 **各子服务的配置入口**、**环境变量习惯**，以及部署与联调时 **容易出错或仍需人工注意** 的点。可与 [`jnaaippt_architecture_v1.md`](jnaaippt_architecture_v1.md)、[`jnadigital_human_data_flow.md`](jnadigital_human_data_flow.md)、[`修缮与功能总结.md`](修缮与功能总结.md) 对照阅读。

## 1. 总览

| 服务/组件 | 典型端口 | 主要配置文件或目录 | 启动入口（见 `start_all.sh`） |
|-----------|----------|-------------------|------------------------------|
| PaddleOCR | 8802 | `paddleocr/.env`，`api_paddleocr_vl_*.py` | `python api_paddleocr_vl_ai_ppt.py` |
| IndexTTS | 6006 | `index-tts-vllm/server/.env` | `python server/tts_server_v2_batch.py` … |

## 2. digital_human_interface（核心业务 API）

### 2.1 配置文件位置

| 路径 | 作用 |
|------|------|
| `digital_human_interface/config/settings.py` | Pydantic `Settings`：目录、`HOST`/`PORT`、`CORS_ORIGINS`、`LIBREOFFICE_PATH`、`FFMPEG` 等 |
| `digital_human_interface/config/config.py` | `get_settings()` 单例加载 |
| `digital_human_interface/.env` | 运行时覆盖（**不提交敏感内容到公开仓库**）；`settings.py` 中 `env_file = ".env"` |
| `digital_human_interface/.env.example` | 示例（当前偏精简，与完整部署项可能不一致，以 `settings.py` 为准） |

### 2.2 常见问题与风险

1. **子服务 URL 未走 Settings**  
   `routers/files.py` 中口播解析、`routers/my_digital_human.py` 中 TTS / Wav2Lip 地址仍多为 **代码内写死的 `http://127.0.0.1:端口/...`**。换端口或跨机部署时需改源码或后续抽象为环境变量。

2. **LibreOffice**  
   `LIBREOFFICE_PATH` 默认偏向 Windows 路径；Linux 下需在 `.env` 中设为本机 `soffice` 实际路径，否则 PPT→PDF 失败。

3. **CORS**  
   `CORS_ORIGINS` 需在 `.env` 中列出浏览器真实访问来源（含协议、域名、端口）；内网 IP 变更后旧条目会残留（参见现有 `.env` 中多地址并列的写法）。

4. **管理控制台**  
   `main.py` 中管理员账号/口令为硬编码，生产环境必须修改并限制网络访问（详见 [`jnadigital_human_console.md`](jnadigital_human_console.md)）。

5. **自定义数字人删除后列表仍显示（已修复）**  
   ≥ 2026-04-20 版本中，`routers/my_digital_human.py` 的删除接口在清除磁盘文件后同步更新 `static/Digital_human/Customized_digital_human.json`，删除操作现可实时生效。

6. **文件清理服务误删视频列表文件（已修复）**  
   ≥ 2026-04-21 版本中，`cleanup_service.py` 的 `cleanup_unreferenced_files()` 已重写。  
   - **原问题**：清理逻辑用 `video_path` 文件名匹配 `images/` 和 `hls/` 下的文件夹，但这些文件夹以 UUID 命名，永远匹配不上，导致每次清理都把所有幻灯片图片和 HLS 切片误判为"未引用"而全部删除。  
   - **修复后**：清理范围收窄为仅清理临时/缓存目录（`static/audio/`、`static/video/temp/`、`static/file/uploads/`、`static/file/bgm/`）。合并视频（`static/video/mergers/`）、幻灯片图片（`static/file/images/`）、HLS 切片（`static/video/hls/`）、PDF（`static/file/pdf/`）均受保护，清理服务不会访问。  
   - 控制台"系统控制"页的文件清理描述已同步更新。

## 3. PaddleOCR（解析 / 口播文案等）

### 3.1 配置文件位置

| 路径 | 作用 |
|------|------|
| `paddleocr/.env` | 模型目录 `VL_MODEL_DIR`、`LAYOUT_MODEL_DIR`、`UPLOAD_BASE_DIR`、`UPLOAD_BASE_URL` 等（**强依赖本机路径与部署 IP**） |
| `paddleocr/api_paddleocr_vl_ai_ppt.py` | 服务端口（可用环境变量）、**CORS 允许列表**（代码内多行 URL） |
| `paddleocr/api_paddleocr_vl_mineru.py` | 另一入口，端口等默认值 |
| `paddleocr/get_api_server_ai_ppt.py` | 客户端默认 `API_URL`（调用本服务 OCR） |

### 3.2 常见问题与风险

1. **绝对路径与 IP**  
   `.env` 中常见 `/home/...` 与公网/内网 IP；换机器或迁云后必须整体替换，否则模型找不到或回传 URL 错误。

2. **CORS 写死在代码里**  
   新增前端域名或端口时，除 `digital_human_interface` 的 CORS 外，还需改 **Paddle 服务** 的允许列表（若浏览器直连 Paddle）。

3. **端口与 digital_human_interface 不一致**  
   业务默认认为解析在 **8802**（`files.py` 写死）；若 Paddle 改端口，必须同步改调用 URL。

## 4. IndexTTS（语音合成）

### 4.1 配置文件位置

| 路径 | 作用 |
|------|------|
| `index-tts-vllm/server/.env` | `HOST`、`PORT`（常用 6006）、`MODEL_DIR`、各类 GPU/显存参数、`REF_AUDIO_ROOT_PATH`、`DEFAULT_OUTPUT_PATH`、`UPLOAD_TEMP_PATH` 等 |
| `index-tts-vllm/server/tts_server_v2_batch.py` | 入口脚本；`PORT` 等可被命令行与环境变量覆盖 |
| `index-tts-vllm/.env.example` | 示例（若存在） |

### 4.2 常见问题与风险

1. **绝对路径**  
   模型与输出目录多为本机绝对路径；仓库克隆到新目录后必须改 `.env`。

2. **显存与批处理参数**  
   `GPU_MEMORY_UTILIZATION`、`IS_FP16` 等与机器相关；OOM 时需调低，与 `start_all.sh` 里命令行参数保持一致（脚本中的 `--gpu_memory_utilization` 等会覆盖部分行为，以实际启动命令为准）。

3. **端口与调用方**  
   `digital_human_interface` 中 TTS 默认指向 **6006**；改端口需同步 `my_digital_human.py` 等处。

4. **示例脚本**  
   `api_example.py`、`test/simple_test.py` 等仍可能写死 `6006` 或 `localhost`，仅作本地测试，不参与生产链路时需留意勿误用。

5. **`start_all.sh` 与 `server/.env` 谁生效？**  
   `start_all.sh` 中 TTS 启动命令若带有 **`--gpu_memory_utilization`、`--qwenemo_gpu_memory_utilization`、`--is_fp16`** 等参数，则 **命令行优先**；未在命令行出现的项仍可用 **`index-tts-vllm/server/.env`** 中的 `PORT`、`MODEL_DIR` 等。仅执行 `python server/tts_server_v2_batch.py` 且不传参时，主要依赖 `.env` 与代码默认值。

## 5. Wav2Lip + MuseTalk（口型 / 生成接口）

### 5.1 配置文件位置

| 路径 | 作用 |
|------|------|
| `wav2lip_workspce/lx/测试/config.py` | `PORT`（默认 5000）、Wav2Lip 路径、**MuseTalk 模型路径与优化参数** |
| `wav2lip_workspce/lx/digital_human_project/config.py` | 镜像/备份目录下同类配置 |
| `wav2lip_workspce/lx/测试/main.py` | 应用入口 |

当前目录 **未必** 提供与 TTS 同级的 `.env` 模板，端口常依赖 **`start_all.sh` 启动环境** 或手动 `export`。

**MuseTalk 相关环境变量**（均可选，有合理默认值；与 `config.py` 中属性一一对应）：

| 环境变量 | 默认值 | 说明 |
|----------|--------|------|
| `MUSETALK_DIR` | `{project_root}/MuseTalk` | MuseTalk 代码根目录 |
| `MUSETALK_UNET_CONFIG` / `MUSETALK_UNET_PATH` / `MUSETALK_WHISPER_DIR` | 见 `config.py` | UNet 配置、权重、Whisper 资源目录 |
| `MUSETALK_VAE_TYPE` | `sd-vae` | VAE 类型 |
| `MUSETALK_USE_FLOAT16` | `true` | 是否使用 FP16 推理（显著降低显存） |
| `MUSETALK_BATCH_SIZE` | `8` | UNet 推理初始 batch（运行时会按显存自适应上调） |
| `MUSETALK_GPU_ID` | `0` | 使用的 GPU 编号 |

**模型预加载**：`main.py` 在启动时依次调用 `_preload_wav2lip()`、`_preload_whisper()`、`_preload_musetalk()`；MuseTalk 预加载失败时仅打印警告，首次 HD 请求仍会走 `_init_musetalk()` 懒加载。**不再使用** `PRELOAD_MUSETALK` 环境变量开关。

### 5.2 常见问题与风险

1. **与编排脚本的工作目录**  
   `start_all.sh` 固定从 `wav2lip_workspce/lx/测试` 启动；若实际工程只在 `digital_human_project` 下维护，需自行统一路径，避免双份逻辑漂移。

2. **端口 5000**  
   `digital_human_interface` 写死 Wav2Lip 为 **5000**；变更端口必须改调用方。

3. **资源路径**  
   模型、音效等路径若在代码或配置中写死，换机需逐项检查（历史上曾做过相对仓库根的路径整理，以当前代码为准）。

4. **音效目录：`lx/测试` 与 `digital_human_project` 两套路径**  
   `config.py` 以 **`__file__` 所在目录** 为 `_base`，默认音效在 **`{_base}/assets/sfx/`** 下三个文件名（完成提示音 / 转场 / BGM）。**`start_all.sh` 从 `lx/测试` 启动**，因此运行中的进程读取的是 **`wav2lip_workspce/lx/测试/assets/sfx/`**。若只把音频放在 **`digital_human_project/assets/sfx/`**，而服务仍从 **`测试`** 目录启动，会出现「已拷贝文件但仍引用失败」。解决办法：在 **`测试/assets/sfx/`** 放置同名文件，或设置环境变量 **`SFX_NOTIFICATION` / `SFX_TRANSITION` / `SFX_BGM`** 指向实际绝对路径。

5. **`image_output/` 残留**  
   Wav2Lip 单页合成结果默认落在 **`lx/测试/image_output/`**（或配置中的 `output_dir`）。**控制台「视频管理」删除**只清理 **`digital_human_interface/static/`** 下与 `basic_information.json` 关联的路径，**不会**删除 Wav2Lip 目录中的 `image_output`；需运维侧单独清理或后续加自动化策略。

6. **多任务后 GPU 显存堆积（已修复）**  
   ≥ 2026-04-20 版本中，`wav2lip_model.py` 的 `_process_batch` 完成后立即释放 GPU tensor（`del img_t, mel_t`），`infer()` 及异常分支均调用 `torch.cuda.empty_cache()`；`video_generator.py` 每个任务正常结束时调用 `_release_gpu_memory(scope="task")`（内部含 `clear_video_cache()` + `empty_cache()`）。**取消或异常**时调用 `_release_gpu_memory(scope="full")`（额外 `gc.collect()`）。MuseTalk `run_musetalk` 的 `finally` 中会结束合成线程、终止 FFmpeg 子进程、释放 GPU 锁并 `empty_cache()`。若升级后仍出现显存持续增长，请确认以**最新代码重启** 5000 服务。

7. **MuseTalk 高清模式集成（2026-04-21，2026-04-25 更新）**  
   - 5000 服务同时承载 Wav2Lip（快速模式）和 MuseTalk（高清模式），由 `quality_mode` 参数路由。
   - **conda 环境**：须使用 **MuseTalk** 环境运行 5000 服务（`start_all.sh` 中 `wav2lip` 条目为 `wav2lip|MuseTalk|0|...`），以匹配 PyTorch 2.x、diffusers、mmpose 等 MuseTalk 依赖；勿用仅含旧版 PyTorch 的环境以免预处理/推理失败。
   - **启动预加载**：`main.py` 启动时预加载 MuseTalk（与 Wav2Lip、Whisper 一并），消除首次 HD 约 30s 模型冷启动；预加载失败则回退为首次请求时懒加载。
   - **推理中取消**：`run_musetalk` 在 UNet batch 循环内检查 `cancelled_tasks`，用户调用 `POST /cancel/{task_id}` 后可尽快中止（仍受单 batch 耗时约束）。
   - **9088 网关超时**：HD 模式轮询从 5 分钟提升到 15 分钟（`poll_task_status_async` 的 `max_attempts=450`）。
   - **9088 取消局限**：前端断开 SSE 不会自动向 5000 发送取消；多页任务中已提交的子任务需依赖 5000 侧取消 API 或等其自然结束。
   - **环境验证（≥ 2026-04-25）**：`main.py` 启动时打印 `[ENV]`（Python 版本、解释器路径、conda 名）并尝试导入 mmpose / einops / diffusers；缺依赖会在日志中明确警告。`start_all.sh` 在激活 conda 后为每个服务打印一行 `which python` 与版本，便于核对 5000 是否真在 **MuseTalk**。若进程误跑在 **wav2lip_fixed（Python 3.8）**，会出现 HD 报 `No module named 'mmpose'`、快速模式在并行收尾时报 `cancel_futures` 等；请执行 `./start_all.sh restart wav2lip` 并核对 `logs/wav2lip.log` 或 `/proc/<PID>/environ` 中的 `CONDA_PREFIX`。
   - 已修复 `audio_processor.py` 越界 `exit()` 崩溃、`get_landmark_and_bbox` 参数名错误、mediapipe 缺失等问题。
   - 详细说明参见 [musetalk_integration.md](musetalk_integration.md)。

9. **V2.3.5 MuseTalk 性能优化与质量修复（2026-04-22）**  
   - **持久化预处理缓存**：DWPose/VAE/FaceParsing 结果缓存到 `musetalk_cache/` 目录，后续请求直接加载（~3s），预处理从 ~150s 降至 ~3s。
   - **缓存 hash 修复**：hash 算法改为纯内容 hash（文件大小 + 首尾各 64KB），不再依赖 mtime。临时文件与原始文件能正确匹配缓存。
   - **NVENC 硬件编码**：FFmpeg 管道输出改用 `h264_nvenc` GPU 编码，编码速度提升 3-5 倍。
   - **Producer-Consumer 流水线**：UNet 推理与帧合成通过 `queue.Queue` 并行执行，推理与合成重叠。
   - **MediaPipe 0.10.x 适配**：`create_person_mask_video` 适配新版 Task API（`ImageSegmenter`），修复 HD 模式背景扣除失败问题。自动下载 `selfie_segmenter.tflite` 模型到 `assets/mediapipe/`。
   - **HD 时间估算修复**：基于实测数据重写估算公式（中文 TTS 0.4s/字、UNet ~10s/batch），偏差从 11.5 倍降至合理范围。
   - **缓存管理 API**：新增 5 个端点（`/musetalk/cache/status`、`/musetalk/preprocess`、`/musetalk/preprocess-all`、`DELETE /musetalk/cache/{hash}`、`DELETE /musetalk/cache`）。
   - **自动预处理**：上传新数字人时自动触发后台预处理。
   - 缓存总占用约 1.25 GB（10 个数字人），存储在 `wav2lip_workspce/lx/测试/services/musetalk_cache/`。

8. **数字人输出质量优化（2026-04-21）**  
   - **背景抠除**：`create_person_mask_video` 已从硬二值化改为软边缘 mask（形态学清理 + 渐变阈值 + 21×21 高斯模糊），边缘锯齿大幅减少。
   - **面部增强**：`_process_batch` 中 Wav2Lip 贴回前增加 Unsharp Mask 锐化（`_sharpen_face`）和椭圆羽化融合，消除矩形硬边。纯 CPU 操作，零显存开销。
   - **编码质量**：所有 `libx264` 命令统一 `-crf 18 -preset medium`（原为默认 CRF 23）。
   - **GFPGAN 已弃用**：初始方案引入 GFPGAN 逐帧面部修复，但速度慢 10 倍且额外占用 ~11GB 显存，已替换为上述轻量方案。

   修改 `.env` 后需重启 `vite`  dev server 并重新构建生产包。

## 7. 其他前端目录（new_frontend）与部署目录（frontend / dist）

| 路径 | 作用 |
|------|------|
| `new_frontend/` | 另一套 Vue + Vite 工程（如 Element Plus），**不是** `setup_env.sh` 默认构建源 |
| `new_frontend/vite.config.ts` | 开发代理 `proxy` 默认指向 `http://127.0.0.1:9088` |
| **`frontend-new/dist/`** | **生产 Nginx 静态根（推荐）**：`vite build` 直接输出至此，无需再拷贝到 `frontend/` |
| **`frontend/`** | **可选副本**：`setup_env.sh` 在构建后仍会将 `dist/` 同步到此处，便于旧配置或备份；新部署以 Nginx `root` 指向 `frontend-new/dist` 为准 |
| **`nginx-myweb.conf`**（仓库根） | 与线上 `/etc/nginx/sites-enabled/myweb` 对齐的备份；其中 `root` 为 `.../PPTTalK/frontend-new/dist` |

**主线**：开发 **`frontend-new`** → `npm run build` → **Nginx `root` → `frontend-new/dist`**。**`new_frontend`** 仅在与团队约定时使用，避免与 `frontend-new` 混淆。

## 8. 仓库级脚本（与配置的关系）

| 文件 | 作用 |
|------|------|
| `start_all.sh` | 定义各服务 **conda 环境、工作目录、启动命令、端口**；控制台启停子进程也依赖其中的 `start_all.sh` 路径 |
| `setup_env.sh` | 一键部署时生成/提示 **conda、路径、部分 env 片段**（如 `CORS_ORIGINS`、`UPLOAD_BASE_URL`）；内容随机器变化 |

**注意：** `start_all.sh` 内 **端口与命令写死在 `SERVICES` 数组**；与 `.env` 不一致时，以**实际监听端口**为准并同步调用方。

## 9. 跨服务共性问题（检查清单）

| 现象 | 可能原因 |
|------|----------|
| 口播生成失败 | Paddle 未起、端口非 8802、或 `files.py` URL 未改 |
| TTS 无响应 | IndexTTS 未起、6006 未监听、显存不足崩溃 |
| 数字人视频卡住 | Wav2Lip 未起、5000 不通、GPU OOM |
| HD 模式「成功: 0, 失败: N」| 9088 轮询超时（需确认 HD 模式 15 分钟超时已生效）；或 MuseTalk 推理异常（查 wav2lip.log） |
| MuseTalk CUDA OOM | 降低 `MUSETALK_BATCH_SIZE`；确保 `MUSETALK_FP16=true`；检查 GPU 0 是否被其他进程占用 |
| HD 模式缓存未命中 | 确认 V2.3.5+ 代码已部署（hash 算法已修复）；运行 `POST /musetalk/preprocess-all` 重建缓存 |
| HD 模式人物带背景 | 确认 MediaPipe ≥ 0.10.x 且 `assets/mediapipe/selfie_segmenter.tflite` 存在；V2.3.5 已修复 |
| 浏览器 CORS 报错 | `digital_human_interface` 与（若直连）Paddle 的允许源未包含前端 Origin |
| 迁机后全挂 | 各服务 `.env` 仍为旧绝对路径或旧 IP |
| 控制台显示服务「已停止」 | `main.py` 用 `127.0.0.1` 探测固定端口；服务未起或端口不一致 |
